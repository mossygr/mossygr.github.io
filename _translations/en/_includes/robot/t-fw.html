From the first upload to the first test

Firmware is the program that runs on the ESP32-CAM. We first upload it from the computer using the MB base; the same board then serves the control page over Wi-Fi. We will work through this in order, never connecting USB and battery power together.

Download and extract the firmware ZIP. It contains the robot_firmware directory, with the main file and six headers. Before uploading, read the clarification about your audio arrangement.

1. Prepare Arduino IDE

  1. Arduino IDE 2.x → File → Preferences → Additional boards manager URLs:
    https://espressif.github.io/arduino-esp32/package_esp32_index.json
  2. Tools → Board → Boards Manager → Espressif “esp32”, version 3.x; the original guide reports testing 3.3.6.
  3. Open the robot_firmware directory, containing robot_firmware.ino and its .h files.
  4. In robot_config.h, change at least AP_PASSWORD, using 8+ characters, and OTA_PASSWORD.
  5. Tools settings:
    • Board: AI Thinker ESP32-CAM. This board enables PSRAM automatically; if selecting “ESP32 Dev Module”, set PSRAM to Enabled.
    • Partition Scheme: Minimal SPIFFS (1.9MB APP with OTA/128KB SPIFFS). Select this FROM THE FIRST upload for OTA to work. The default “Huge APP” leaves no OTA space; the firmware then prints a Serial warning and does not enable OTA.
    • Upload Speed: if uploading stops partway through, choose 115200.
    • Port: the MB base's CH340 port.

2. Make the first upload using the MB base

  1. Switch off the robot. Unplug the ESP32-CAM from the robot's Dupont leads and fit it onto the MB with the camera facing up, matching the labels: the ESP32-CAM's 5V/GND must sit over the MB's 5V/GND. On most MB boards, the microSD/5V end faces USB. Each row has eight pins, so it can also fit backwards: check twice.
  2. Connect USB to the computer. If no port appears, install the CH340 driver.
  3. Press Upload. If it stalls at “Connecting…”, hold IO0 on the MB, press RST on the ESP32-CAM, then release IO0.
  4. Open Serial Monitor at 115200 and press RST. If nothing appears, press RST on the ESP32-CAM again. You should see “Access Point "Robot-4WD"” and http://192.168.4.1.
  5. Disconnect USB, remove the ESP32-CAM from the MB, and reconnect the robot wiring, with 5V/GND/IO in the correct positions shown in the table.
Never USB and battery together The MB feeds 5V directly to the board. If the robot is on, the two supplies are connected against each other.

3. Connect the phone and make a small test

By default, the robot creates its own Access Point (AP). The phone joins it like an ordinary Wi-Fi network, but the robot does not provide Internet access. The camera and controls work locally.

  1. Raise the robot so that the wheels do not touch the ground. Turn on the switch.
  2. On the phone, open Settings → Wi-Fi → Robot-4WD, using the AP_PASSWORD password. If the phone reports “no Internet”, choose to remain connected.
  3. Open http://192.168.4.1 in the browser. The camera is at the top, with joystick, light, and audio controls below. The dot beside the title turns green when connected.
  4. Push the joystick slightly forward: all four wheels should turn forwards. If a whole side runs backwards, change INVERT_LEFT/INVERT_RIGHT. If left and right are swapped, exchange the OUT1/2 ↔ OUT3/4 pairs.
  5. If no new movement command arrives for more than 500 ms, the code requests zero speed and the ramp reduces output toward zero. This is the communication failsafe, not a promise that the wheels physically stop at exactly half a second.

Optionally, to join home Wi-Fi as a Station (STA), enter STA_SSID/STA_PASSWORD; the IP appears in Serial Monitor. The supplied ZIP waits up to 20 s, controlled by STA_TIMEOUT_MS 20000. If it cannot connect, it runs network diagnostics and returns to Access Point mode. The original instructions said 10 s; the difference is recorded with the downloads.

4. Add the audio files

  1. Connect the DFPlayer Pro to the computer with a USB-C cable. It can remain mounted, but the robot should preferably be switched off. It appears as a 128MB USB drive.
  2. Copy files to the drive's root as 01.mp3, 02.mp3, and so on, in that order, one at a time. Preferably use mono, 128 kbps files.
  3. “♪ 1” plays the first file, and so on. With TRACK_BY_FILENAME 0, the default, numbering follows copy order. To select by filename instead, set TRACK_BY_FILENAME 1. TRACK_COUNT determines how many buttons appear.
  4. Use “Safely remove” before unplugging USB-C.
If it plays automatically at every startup (optional) Some DFPlayer modules start playing when powered on. In that case: (1) create a ~1 s silent file named silence.mp3; (2) copy it to the drive's root LAST, after all songs, otherwise button numbers shift; (3) set DFP_STOP_ON_BOOT 1 in robot_config.h and upload again. The robot plays the silent file at startup and the module stops.
Volume The DFPlayer sends no response because its TX is unconnected. The displayed volume is therefore the last value sent by the robot. It starts at DFP_DEFAULT_VOLUME, 20. On every power-on, the robot resends its settings: no spoken startup message and one track at a time.

5. What changes for later upgrades

OTA means upgrading over the network: the next program arrives through Wi-Fi instead of USB. Suitable memory partitioning is needed from the first USB upload, which is why the earlier Partition Scheme choice matters from the start.

With the phone or laptop connected to “Robot-4WD”, Arduino IDE shows a network port named robot4wd. Select it and press Upload; it asks for OTA_PASSWORD. The motors stop automatically during the upgrade.

The main functions at a glance

If the first test behaved as expected, we now have a camera, movement control, light, and an audio path. The figures below are a useful reference; next we will look at the code behind each behaviour.

  • MJPEG camera on port 81, /stream; control page on port 80; WebSocket control through /ws at ~20 messages per second, with HTTP /control as a fallback.
  • 1 kHz, 8-bit PWM on IN1–IN4, LEDC channels 2–5; 65% limit, 30% minimum, gradual acceleration, 500 ms failsafe.
  • GPIO4 flash on LEDC channel 6, with adjustable brightness.
  • DFPlayer Pro controlled through AT commands on GPIO2 at 115200 baud.
