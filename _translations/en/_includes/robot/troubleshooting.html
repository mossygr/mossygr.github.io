If the first test does not go as expected

Before changing settings or moving several wires at once, identify where the problem appears. Start with what you can observe and make one change at a time, with the power off whenever you touch the connections.

The board resets as soon as the motors move or the light comes on.
Check power first: battery charge, C1 polarity, and the length and thickness of #11/#12. The detailed sequence is in symptoms. Do not start by trying to hide a voltage drop through speed changes in the code.
The upload remains at “Connecting…”.
Return to the MB base upload step and check the port, orientation, and IO0/RST procedure. The specific IO2 case is covered in the ESP32-CAM notes; it is not a reason to disconnect random wires.
One wheel turns backwards, or a whole side runs in reverse.
These are two different cases. For one motor, check that motor's polarity. For a whole side, use INVERT_LEFT/INVERT_RIGHT. See the L298N and motor section for details. Test with the wheels off the ground.
The camera freezes, although the page has loaded.
Close other devices or tabs using the stream. The guide supports one device at a time. The code explanation shows how the interface monitors the stream and tries to restore it.
There is no sound, or a button plays the wrong file.
Start with the selected audio arrangement, the common ground, and the MP3 copying order. The DFPlayer's TX does not report status back to the ESP32-CAM, so the volume display shows the last value sent, not a confirmed measurement from the module.
