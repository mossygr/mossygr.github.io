Καταλαβαίνουμε τον κώδικα, βήμα βήμα

Αφού δεις το ρομπότ να ανταποκρίνεται, αξίζει να κοιτάξεις τι συμβαίνει μέσα του. Δεν χρειάζεται να διαβάσεις και τα επτά αρχεία από την αρχή μέχρι το τέλος. Ακολούθησε πρώτα μία απλή ερώτηση: τι γίνεται από τη στιγμή που σπρώχνω το joystick μέχρι να κινηθούν οι ρόδες;

Τα παρακάτω αποσπάσματα προέρχονται αυτούσια από το ZIP του οδηγού. Δείχνουν συγκεκριμένα σημεία του προγράμματος· για να το ανεβάσεις στην πλακέτα, χρησιμοποίησε ολόκληρο τον φάκελο robot_firmware, όχι τα αποσπάσματα μόνα τους.

Ένας χάρτης για τα επτά αρχεία

robot_firmware.ino
Ξεκινά τα υποσυστήματα, συνδέεται στο Wi-Fi και εκτελεί τον κύριο βρόχο.
robot_config.h
Συγκεντρώνει τους κωδικούς, τα pin, τα όρια ταχύτητας και τις υπόλοιπες ρυθμίσεις.
robot_motors.h
Μετατρέπει το joystick σε κίνηση για την αριστερή και τη δεξιά πλευρά, με σταδιακές αλλαγές και έλεγχο απώλειας εντολών.
robot_camera.h
Ρυθμίζει την κάμερα και τη μνήμη που χρησιμοποιεί για τα καρέ.
robot_web.h
Εξυπηρετεί τη σελίδα, τις εντολές και τη ροή εικόνας. Εδώ βρίσκεται και ο χειρισμός του φωτός.
robot_web_ui.h
Περιέχει τη σελίδα HTML και τη JavaScript που τρέχουν στον browser του κινητού.
robot_audio.h
Στέλνει τις εντολές αναπαραγωγής και έντασης στο DFPlayer Pro.

Μια χρήσιμη πρώτη διάκριση: ο κώδικας C++ τρέχει στην ESP32-CAM. Η JavaScript του robot_web_ui.h τρέχει στο κινητό. Οι δύο πλευρές επικοινωνούν μέσα από το Wi-Fi.

Τι γίνεται μόλις ανοίξει το ρομπότ

Η setup() εκτελείται μία φορά στην εκκίνηση. Πρώτα κρατά χαμηλά τα pin των μοτέρ και σβήνει το φλας. Ύστερα ετοιμάζει την οδήγηση, το φως, την κάμερα και τον ήχο. Τελευταία ξεκινά το Wi-Fi, τους web servers και, εφόσον υπάρχει η κατάλληλη κατάτμηση μνήμης, την αναβάθμιση μέσω Wi-Fi.

Η loop() επαναλαμβάνεται συνεχώς:

{% capture firmware_excerpt_1 %} ```cpp void loop() { motors::update(); // ράμπα + failsafe 500 ms light::update(); audio::update(); // στέλνει τις εντολές AT από την ουρά #if ENABLE_OTA if (s_otaReady) ArduinoOTA.handle(); #endif delay(2); } ``` {: file="robot_firmware.ino" } {% endcapture %} {{ firmware_excerpt_1 | markdownify }}

Κάθε πέρασμα δίνει στα μοτέρ την ευκαιρία να πλησιάσουν την ταχύτητα-στόχο, εφαρμόζει τυχόν αλλαγή φωτός και στέλνει την επόμενη εντολή ήχου. Το ArduinoOTA.handle() εξυπηρετεί τις ασύρματες αναβαθμίσεις όταν το OTA είναι έτοιμο. Το delay(2) είναι μια μικρή παύση, όχι εντολή να κινηθεί το ρομπότ για δύο δευτερόλεπτα.

Οι HTTP handlers εξυπηρετούνται από τους servers που ξεκίνησε η web::begin(). Γι’ αυτό δεν θα βρεις κάποια web::update() μέσα στη loop().

Από το δάχτυλο σε μια εντολή

Στο κινητό, η θέση του joystick γίνεται δύο αριθμοί: x για αριστερά/δεξιά και y για πίσω/μπροστά, από −100 έως 100. Όσο το κρατάς, η σελίδα στέλνει τη θέση περίπου κάθε 50 ms, δηλαδή 20 φορές το δευτερόλεπτο.

Για παράδειγμα, J,20,60 σημαίνει «λίγο δεξιά και αρκετά μπροστά». Το μήνυμα φτάνει στο /ws, τη σύνδεση WebSocket: ένα κανάλι που μένει ανοιχτό για να ανταλλάσσονται μικρά μηνύματα. Στο robot_web.h, η εντολή αναγνωρίζεται εδώ:

{% capture firmware_excerpt_2 %} ```cpp case 'J': if (readInt(p, -1000, 1000, &a) && *p++ == ',' && readInt(p, -1000, 1000, &b)) { motors::setJoystick(a, b); return true; } break; ``` {: file="robot_web.h" } {% endcapture %} {{ firmware_excerpt_2 | markdownify }}

Η σελίδα ξαναδοκιμάζει τη σύνδεση όταν χαθεί. Μετά από τρεις αποτυχίες WebSocket ενεργοποιεί εφεδρικές HTTP αιτήσεις: /control για το joystick και /cmd για τις υπόλοιπες εντολές. Οι δύο τρόποι καταλήγουν στις ίδιες λειτουργίες ελέγχου του firmware.

Όταν αφήσεις το joystick, το κινητό στέλνει J,0,0 τρεις φορές, με διαφορά 60 ms. Αν η καρτέλα περάσει στο παρασκήνιο, επιχειρεί επίσης να στείλει εντολή στάσης.

Πώς στρίβει χωρίς τιμόνι

Το ρομπότ έχει δύο ομάδες κίνησης: τα δύο αριστερά μοτέρ και τα δύο δεξιά. Για να στρίψει, αλλάζει τη σχέση των δύο πλευρών. Ο βασικός υπολογισμός στη motors::setJoystick() είναι:

{% capture firmware_excerpt_3 %} ```cpp int l = y + x; int r = y - x; // κανονικοποίηση ώστε |l|,|r| ≤ 100 χωρίς να χαλάει η αναλογία int m = max(abs(l), abs(r)); if (m > 100) { l = l * 100 / m; r = r * 100 / m; } ``` {: file="robot_motors.h" } {% endcapture %} {{ firmware_excerpt_3 | markdownify }}

Με x = 0, οι δύο πλευρές παίρνουν την ίδια τιμή και το ρομπότ προχωρά ευθεία. Με x = 20 και y = 60, προκύπτουν αριστερά 80 και δεξιά 40: η αριστερή πλευρά ζητά μεγαλύτερη ταχύτητα, ώστε να στρίψει δεξιά. Αν το απόλυτο μέγεθος κάποιας τιμής ξεπεράσει το 100, η κανονικοποίηση μικραίνει και τις δύο κρατώντας την αναλογία τους.

Πριν από αυτόν τον υπολογισμό, το πρόγραμμα περιορίζει τις εισόδους στο −100…100 και αγνοεί αποκλίσεις μικρότερες από 8% σε κάθε άξονα. Μετά εφαρμόζει τα INVERT_LEFT και INVERT_RIGHT, αν χρειάζεται αντιστροφή κάποιας πλευράς.

Το αποτέλεσμα δεν πηγαίνει κατευθείαν στο μοτέρ ως ποσοστό. Η pctToDuty() το μετατρέπει σε τιμή PWM. Το PWM ανοιγοκλείνει γρήγορα την έξοδο· το duty δείχνει τι μέρος κάθε κύκλου παραμένει ενεργό. Οι συγκεκριμένες ρυθμίσεις του ZIP είναι:

{% capture firmware_excerpt_4 %} ```cpp #define MAX_DUTY 166 // ≈ 65 % #define MIN_DUTY 77 // ≈ 30 %, κάτω από αυτό δεν ξεκινούν #define JOY_DEADZONE 8 // % – νεκρή ζώνη joystick #define RAMP_UP_STEP 6 // μέγιστη αύξηση duty ανά βήμα (επιτάχυνση) #define RAMP_DOWN_STEP 20 // μέγιστη μείωση duty ανά βήμα (φρενάρισμα) #define RAMP_PERIOD_MS 10 // βήμα ράμπας #define FAILSAFE_MS 500 // σταματά αν δεν έρθει εντολή τόσο χρόνο ``` {: file="robot_config.h" } {% endcapture %} {{ firmware_excerpt_4 | markdownify }}

Με ανάλυση 8 bit, η κλίμακα είναι 0…255. Το 166 αντιστοιχεί περίπου σε 65% και το 77 περίπου σε 30%. Η μηδενική εντολή παραμένει μηδέν· μια μη μηδενική εντολή μεταφέρεται στο εύρος ανάμεσα σε αυτά τα όρια. Από στάση, η ράμπα ξεκινά στο ελάχιστο duty και κατόπιν πλησιάζει τον στόχο, αντί να ζητά αμέσως τη μέγιστη τιμή.

Σημαντικό για να καταλαβαίνεις τη ρύθμιση: το PWM δεν είναι σταθεροποιητής τάσης. Το όριο είναι παράμετρος του συγκεκριμένου firmware, όχι μέτρηση της πραγματικής τάσης ή του ρεύματος των μοτέρ.

Τι γίνεται αν χαθεί η εντολή οδήγησης

Κάθε αποδεκτή εντολή joystick ενημερώνει τη χρονική σφραγίδα s_lastCmdMs. Αν περάσουν περισσότερα από 500 ms χωρίς καινούργια εντολή, η motors::update() κάνει αυτό:

{% capture firmware_excerpt_5 %} ```cpp if ((int32_t)(millis() - s_lastCmdMs) > (int32_t)FAILSAFE_MS) { s_targetL = 0; s_targetR = 0; } ``` {: file="robot_motors.h" } {% endcapture %} {{ firmware_excerpt_5 | markdownify }}

Μηδενίζει τους στόχους και η ράμπα οδηγεί τις εξόδους προς το μηδέν. Άρα τα 500 ms είναι το όριο αναγνώρισης της απώλειας εντολών, όχι υπόσχεση ότι οι ρόδες ακινητοποιούνται μηχανικά ακριβώς τότε.

Το μήνυμα P είναι ξεχωριστό: ζητά την κατάσταση του ρομπότ και βοηθά τη σελίδα να δείχνει αν υπάρχει σύνδεση. Δεν ανανεώνει τον χρόνο της τελευταίας εντολής οδήγησης. Έτσι μια σύνδεση που ακόμη απαντά στα ping δεν αρκεί από μόνη της για να κρατήσει τα μοτέρ σε κίνηση.

Γιατί η κάμερα έχει δική της θύρα

Η σελίδα ελέγχου ανοίγει στη θύρα 80. Η εικόνα έρχεται χωριστά από τη θύρα 81, στη διαδρομή /stream. Το MJPEG είναι μια διαδοχή εικόνων JPEG που ο browser εμφανίζει ως ζωντανή ροή. Ο χωριστός server κρατά τη συνεχή αποστολή εικόνας μακριά από τον handler των εντολών.

Στο robot_camera.h, η παρουσία PSRAM —της πρόσθετης μνήμης της πλακέτας— καθορίζει τις ρυθμίσεις των καρέ:

{% capture firmware_excerpt_6 %} ```cpp if (psramFound()) { c.frame_size = CAM_FRAME_SIZE; c.jpeg_quality = CAM_JPEG_QUALITY; c.fb_count = 2; c.fb_location = CAMERA_FB_IN_PSRAM; } else { Serial.println("[ΚΑΜΕΡΑ] Δεν βρέθηκε PSRAM – έλεγξε ότι η πλακέτα είναι \"AI Thinker ESP32-CAM\""); c.frame_size = FRAMESIZE_QVGA; c.jpeg_quality = 15; c.fb_count = 1; c.fb_location = CAMERA_FB_IN_DRAM; c.grab_mode = CAMERA_GRAB_WHEN_EMPTY; } ``` {: file="robot_camera.h" } {% endcapture %} {{ firmware_excerpt_6 | markdownify }}

Με τις προεπιλογές του robot_config.h, αυτό σημαίνει VGA 640×480, ποιότητα JPEG 12 και δύο buffers στην PSRAM. Αν δεν βρεθεί PSRAM, το πρόγραμμα χρησιμοποιεί QVGA, έναν buffer στην εσωτερική μνήμη DRAM και διαφορετικό τρόπο λήψης. Αν η αρχικοποίηση της κάμερας αποτύχει, η εκκίνηση συνεχίζεται με σχετικό μήνυμα στο Serial.

Η σελίδα ελέγχει και τον μετρητή καρέ f από την απάντηση κατάστασης. Αν δεν αλλάζει για περίπου τρία δευτερόλεπτα ενώ η εικόνα ήταν ορατή, επιχειρεί επανασύνδεση της ροής. Αυτό είναι διαφορετικό από τον έλεγχο απώλειας εντολών των μοτέρ.

Φως και ήχος χωρίς να περιμένει το joystick

Το φως είναι το ενσωματωμένο λευκό LED στο GPIO4. Οι εντολές L,1/L,0 το ανοίγουν ή το κλείνουν, ενώ η B,n αλλάζει τη φωτεινότητα στην κλίμακα 0…255. Ο web handler αποθηκεύει την επιθυμητή κατάσταση και η light::update() την εφαρμόζει.

Για τον ήχο, το GPIO2 της ESP32 στέλνει σειριακές εντολές στο RX του DFPlayer Pro στα 115200 baud. Το TX του DFPlayer δεν συνδέεται, οπότε το firmware δεν παίρνει επιβεβαίωση από τη μονάδα. Η ένταση που δείχνει η σελίδα είναι η ζητούμενη τιμή που θυμάται το πρόγραμμα, όχι μέτρηση ή απάντηση του DFPlayer.

Η αναπαραγωγή ενός κομματιού περνά από την playTrack():

{% capture firmware_excerpt_7 %} ```cpp inline void playTrack(int n) { if (n < 1) return; s_lastTrack = n; #if TRACK_BY_FILENAME enqueue("AT+PLAYFILE=/%02d.mp3", n); #else enqueue("AT+PLAYNUM=%d", n); #endif } ``` {: file="robot_audio.h" } {% endcapture %} {{ firmware_excerpt_7 | markdownify }}

Με TRACK_BY_FILENAME = 0, η εντολή ζητά το κομμάτι με βάση τη σειρά αντιγραφής. Με τιμή 1, ζητά συγκεκριμένο όνομα, όπως /01.mp3. Οι εντολές μπαίνουν σε ουρά 16 θέσεων και στέλνονται από την audio::update(), μετά την αρχική αναμονή των 1.5 s και με τουλάχιστον 40 ms ανάμεσά τους. Για την ένταση κρατιέται η πιο πρόσφατη εκκρεμής τιμή, ώστε το σύρσιμο του slider να μη γεμίζει την ουρά με ενδιάμεσα επίπεδα.

Εδώ χρειάζεται να ξεχωρίσουμε κώδικα και διάγραμμα

Το ZIP στέλνει AT+AMP=ON και τα σχόλιά του περιγράφουν ηχείο απευθείας στα L+/L− του DFPlayer Pro. Τα διαγράμματα και ο πίνακας του οδηγού περιγράφουν εξωτερικό DFR0119, με DACL → LIN και το ηχείο στον εξωτερικό ενισχυτή. Πρόκειται για δύο διαφορετικές περιγραφές διάταξης ήχου. Η εξήγηση του κώδικα δεν αλλάζει τη συνδεσμολογία του σχεδίου· δες τη συγκεντρωμένη σημείωση διαφορών πριν αποφασίσεις ποια διάταξη ακολουθείς.

Wi-Fi και αναβάθμιση χωρίς τη βάση MB

Αν το STA_SSID είναι κενό, το ρομπότ δημιουργεί το δικό του δίκτυο, το Robot-4WD: αυτή είναι η λειτουργία Access Point, ή AP. Αν συμπληρώσεις τα στοιχεία του σπιτιού, δοκιμάζει να συνδεθεί ως station, ή STA. Στο συγκεκριμένο ZIP το STA_TIMEOUT_MS είναι 20000, δηλαδή 20 s. Αν δεν συνδεθεί μέσα στο όριο, γράφει διάγνωση, σαρώνει τα διαθέσιμα δίκτυα και επιστρέφει σε AP.

Το OTA σημαίνει Over The Air: στέλνεις την επόμενη έκδοση μέσω Wi-Fi. Χρειάζεται κατάλληλη κατάτμηση μνήμης από το πρώτο USB upload. Ο κώδικας ελέγχει αν υπάρχει επόμενη κατάτμηση ενημέρωσης πριν ενεργοποιήσει την υπηρεσία.

Όταν αρχίσει η αναβάθμιση, εκτελείται ο παρακάτω χειρισμός:

{% capture firmware_excerpt_8 %} ```cpp motors::lockOut(); // μοτέρ στο 0 και αγνόηση εντολών joystick light::set(false); light::update(); web::stopStream(); // ελευθερώνει Wi-Fi/CPU από τη ροή κάμερας ``` {: file="robot_firmware.ino" } {% endcapture %} {{ firmware_excerpt_8 | markdownify }}

Η lockOut() μηδενίζει αμέσως τις εξόδους και αγνοεί νέες εντολές joystick. Το φως σβήνει και η ροή κάμερας τερματίζεται. Αυτός ο χειρισμός είναι χωριστός από το συνηθισμένο failsafe, επειδή η διαδικασία ενημέρωσης μπορεί να κρατήσει απασχολημένη τη loop(). Αν αποτύχει η OTA διαδικασία, ο αντίστοιχος error handler επανεκκινεί την ESP32.

Πού κοιτάζω όταν θέλω να αλλάξω κάτι

Για τις συνηθισμένες προσαρμογές ξεκίνα από το robot_config.h. Δεν χρειάζεται να πειράξεις τον server ή τον αλγόριθμο κίνησης για να αλλάξεις έναν κωδικό ή να διορθώσεις μια ανάποδη πλευρά.

  • Δίκτυο και κωδικοί: AP_SSID, AP_PASSWORD, προαιρετικά STA_SSID/STA_PASSWORD, και χωριστά το OTA_PASSWORD.
  • Ανάποδη ολόκληρη πλευρά: INVERT_LEFT ή INVERT_RIGHT. Αν μόνο ένα μοτέρ της ίδιας πλευράς είναι ανάποδα, δες πρώτα τη συνδεσμολογία του.
  • Προσανατολισμός και μέγεθος εικόνας: CAM_VFLIP, CAM_HMIRROR, CAM_FRAME_SIZE. Διατήρησε το pin mapping της συγκεκριμένης AI-Thinker.
  • Ήχος: DFP_DEFAULT_VOLUME, TRACK_COUNT, TRACK_BY_FILENAME. Η προεπιλεγμένη ένταση είναι 20 και τα κουμπιά κομματιών 8.

Άλλαζε ένα πράγμα κάθε φορά. Ανέβασε την έκδοση, κοίτα τα μηνύματα του Serial και επανάλαβε τον αντίστοιχο έλεγχο με τις ρόδες στον αέρα. Έτσι θα ξέρεις ποια αλλαγή έφερε ποιο αποτέλεσμα.
